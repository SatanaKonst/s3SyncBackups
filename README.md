# Синхронизация бэкапов PROXMOX с s3 хранилищем

## ! Только для бэкапов PROXMOX

### Требуется Python 3 и установленный rclone

```
Формат наименованиия бэкапов 
vzdump-qemu-100-2024_02_30-15_42_45.vma.zst
```

Скрипт работает с использованием Rclone (подключение к хранилищу должно быть настроено: `rclone config`).

## Как работает

1. Проверяет разницу между локальной директорией и удаленной.
2. Загружает недостающие файлы, но только в пределах окна ретеншена: окно считается по объединению локальных и облачных копий, поэтому локальные бэкапы старше лимита не «прыгают» в облако и не удаляются оттуда на следующем прогоне.
3. Чистит облако до заданного кол-ва копий на каждую группу VM (регекс `GROUP_BACKUP_REGEX`): удаляет самые старые при превышении лимита. Чистка выполняется при каждом запуске, не только после загрузки.

Дубли имён (`2026_11_06-18_36_01` и `20261106-183601`) считаются одним бэкапом и не грузятся повторно.

### Notes (описания бэкапов)

Если `ADD_NOTES_TO_BACKUP_NAME=Y` и рядом с бэкапом лежит файл `имя.zst.notes`, к имени при загрузке добавляется `_notes:<md5 от .notes>`.
Так бэкапы из разных расписаний (или с изменённым описанием) синхронизируются как разные копии. Изменение `.notes` — новое имя → перезагрузка с новым суффиксом.

## Запуск

1. Скопировать `env` в `.env`
2. Заполнить переменные (в `env` есть примеры регексов)
3. Установить зависимости ```pip install -r requirements.txt```
4. Запустить ```python3 backupsSync.py```

Скрипт валидирует настройки при старте: пустые обязательные переменные, несуществующая локальная директория, некорректные регексы и нечисловой `BACKUP_SAVE_COUNT` — понятная ошибка вместо падения в середине работы.

# Параметры запуска
```
--dry-run - режим эмуляции: ничего не грузит и не удаляет, печатает лог в консоль
--background - запуск в фоне, не ждёт окончания работы; результат придёт в Telegram
--dump-tg - вместо отправки в Telegram пишет сообщение в файл logs/telegram_<timestamp>.txt (токен не нужен)
```

Флаги можно совмещать, порядок не важен.

### Запуск в фоне
```bash
./venv/bin/python3.13 backupsSync.py --background
```
Скрипт сразу вернёт управление и продолжит работать отвязанным процессом (переживает закрытие SSH-сессии).<br>
Лог работы — в папке `logs/`, итог — сообщением в Telegram (если `SEND_TELEGRAM=Y`).<br>
Можно совмещать с `--dry-run`: ```backupsSync.py --dry-run --background``` (вывод dry-run в консоль не попадёт, смотрите лог).<br>
Повторный запуск заблокируется lock-файлом `backup_sync.lock`, пока фоновый процесс не закончит работу (мёртвые lock-файлы убираются автоматически).

### Логи
Каждый запуск создаёт файл в `logs/`. Хранятся 10 последних логов и 10 последних telegram-дампов, остальные удаляются при старте.

## Telegram-уведомления

Два сообщения (длинные дробятся на части):
1. Отчёт: загруженные файлы, удалённые из бакета, ошибки удаления
2. Актуальный список файлов в бакете после синка и чистки

# Переменные env
```
LOG_FILE - название файла лога (по нему же чистятся старые логи)
REMOTE_NAME - название подключения к s3 (из rclone config)
BACKUP_CONTAINER_NAME - название контейнера (бакет)
BACKUP_LOCAL_DIR - путь до локальной дирректории с бэкапами
BACKUP_SAVE_COUNT - кол-во бэкапов на одну группу VM в облаке
SELECTED_BACKUP_REGEX - регулярка для выборки бэкапов
GROUP_BACKUP_REGEX - регулярка для группировки по VM (используется для расчета кол-ва бэкапов)
REMOVE_LOCAL_BACKUP - Y: удалять локальный бэкап после успешной загрузки (локальная ретеншн-чистка остаётся на proxmox)
SEND_TELEGRAM - отправить сообщение в Telegram
TELEGRAM_TOKEN - токен телеги
TELEGRAM_BOT_CHAT_ID - чат в телеге
TG_BASE_URL - базовый URL Telegram API (по умолчанию https://api.telegram.org)
TELEGRAM_MESSAGE_HEADER - Заголовок уведомлениия
ADD_NOTES_TO_BACKUP_NAME - добавляет md5 от файла .notes в имя бэкапа (см. Notes)
BWLIMIT -  ограничение полосы канала (https://rclone.org/docs/#bwlimit-bandwidth-spec)
RCLONE_TRANSFERS - кол-во потоков загрузки
```

Внимание: rclone сам читает переменные `RCLONE_*` из окружения — оставлять их пустыми (`RCLONE_TRANSFERS=`) нельзя, закомментируйте.
